# 测试与复现

本项目提供两层测试：**单元测试（JUnit 5）** 与 **接口级脚本测试（Python）**。

## 一、单元测试

```bash
mvn test
```

覆盖 9 个用例：7 个设计模式有效性验证 + 2 个并发相关用例（详见 `src/test/java/com/campus/card/`）。

- `DesignPatternTest`：验证工厂、策略、责任链、观察者、代理、装饰、适配器各模式按预期协作。
- `ConcurrencyTest`：验证乐观锁扣款在并发下的正确性（需在可连数据库的环境运行）。

## 二、接口级脚本测试（需先启动后端）

脚本仅依赖 Python 标准库，对运行中的后端发真实 HTTP 请求。
先把环境变量指向后端地址（默认 `http://localhost:8080`）：

```bash
export CAMPUS_BASE=http://localhost:8080

# 32 条功能 / 边界 / 异常用例（功能、参数校验、状态拦截等）
python scripts/run_api_tests.py

# 100 线程并发 + 200 请求混合负载（会真实扣款，请在临时库上跑）
python scripts/run_concurrency_tests.py

# 演示数据自检（11 项检查，只读接口）
python scripts/check_demo_data.py
```

> ⚠️ 并发脚本会**真实修改账目**，务必在临时库（如 `campus_card_smoke`）上运行，
> 且先把 `application.yml` 的 `campus.max-qps-per-terminal` 临时调高（如 2000），否则默认 20 次/秒限流会干扰结果。

脚本运行后会在当前目录输出 JSON 结果，可自行核对每条用例的响应码与账目一致性。
**本仓库不再随附固定的"接口实测记录"文档**——上述脚本即为记录的可复现来源，换机器重跑即可获得对应环境的真实响应。

## 三、演示数据生成

演示数据由 `scripts/generate_test_data.py` 生成并同步写入 `sql/init.sql` 与
`src/main/resources/data.sql` 的生成段。如需调整数据量，修改脚本后重跑，
再执行 `sql/init.sql` 即可重建演示库。
